# Bless notes

This directory holds the smoke-test baseline NPY arrays. Each subdir
matches a `SmokeTest.<name>` test in `tests/test_smoke.cpp`. The
comparison contract is in `tests/BlessCompare.{h,cpp}` and
`bless_policy.toml` sits next to this file.

## What "blessed" means here

Snapshot of the calculator output for a known fixture, taken from a
specific commit, against which future runs are compared with the
tolerance + nonzero policy in `bless_policy.toml`. Not bit-identical
re-execution: that contract was retired 2026-05-04 in favour of
tolerance + nonzero sanity, so the same calculator running on a
different platform / LTO / blas build is allowed to drift within tol.

A baseline that no longer matches current code with **drift exceeding
the policy** means one of:

- A calculator regressed (investigate, fix, then re-bless),
- The substrate that feeds a calculator changed deterministically
  (e.g. the ff14SB flat table was regenerated → re-bless and record
  why here), or
- The policy is wrong for this array (tighten or loosen the per-array
  override in `bless_policy.toml`).

### 2026-05-07 — re-bless 6 NPYs in `withdft/` after the OrcaRunLoader H1 backbone-tag fix

Reason: commit `85de965` (2026-05-06, "NamingRegistry: canonicalise at every
loader; close PdbFileReader bypass") removed an aliasing bug in
`OrcaRunLoader::SetupBackboneIndices` where the line

```cpp
else if ((name == "H" || name == "HN" || name == "H1") &&
         res.H == Residue::NONE) res.H = idx;
```

incorrectly tagged the N-terminal `H1` ammonium hydrogen as the residue's
backbone amide H. AMBER ff14SB encodes the protonated +1 N-terminus as
three equivalent NH3+ hydrogens (`H1`, `H2`, `H3` in `kCapNtermCharged`),
all carrying `BackboneRole::None` and `is_cap_only_n=true` in the
substrate (`src/generated/LegacyAmberSemanticTables.cpp:655-660`). They
are cap atoms, not amide hydrogens. The bless-time loader matched only
`H1` (the first of three) which left the residue with one of three
chemically-equivalent ammonium Hs labelled backbone — incoherent under
rotational averaging. ChimeraX (independent first-principles reference)
returns `N, CA, C, O` for `:1 & backbone` on the N-terminal residue —
no Hs.

The fix removes the `H1` alias. The string-matched cache now produces
`res.H = NONE` for any residue whose canonical amide H has been
canonicalised away (which the post-2026-05-06 loader pipeline does
deliberately for cap atoms). The typed substrate-driven cache
(`Protein::CacheResidueBackboneIndices_Typed`, added in commit `a5b4732`
on 2026-05-06) produces the same result: it walks `BackboneRole::AmideHydrogen`
and finds none on N-terminal residues, leaving `res.H = NONE`.

The bless made on 2026-05-04 17:47 captured the pre-fix output.
Pre-fix: `is_backbone[1] = true` (atom 1 = H1 of ILE residue 0).
Post-fix: `is_backbone[1] = false`. `is_backbone[]` for atoms 2 and 3
(H2, H3) was `false` in both versions because the bless-time `&& res.H == NONE`
guard prevented further matches once H1 was set.

Quantitative confirmation: the per-atom delta in
`coulomb_efg_backbone.npy` between bless and current matches the
predicted single-source contribution from atom 1's ff14SB charge
`q(H1) = +0.2329e` evaluated through the dipolar kernel
`V_ab = q · (3 r_a r_b / r^5 − δ_ab / r^3)`. Across all 294 drifted
probe atoms in the 20 Å Coulomb cutoff:

```text
|observed Δ| / |predicted V_1 contribution|
  mean = 1.000   std = 0.000   max = 1.000   min = 1.000
```

The 57 non-drifted probes are all > 20 Å from atom 1 (outside
`coulomb_efield_cutoff`). MOPAC variants drift on 350/351 atoms
because `MopacCoulombResult` does not apply a spatial cutoff — every
probe feels atom 1's contribution.

`mc_category_T2.npy` drifts on exactly 72 atoms (those within
McConnell's 10 Å range of the N–H1 bond). The bond's category flipped
from `BackboneOther` (both endpoints backbone) to `SidechainOther`
(only N is backbone now; H1 isn't). `mc_shielding`, `mc_scalars`,
and the MOPAC McConnell variants are bit-identical because their
totals don't depend on per-category attribution.

NPYs re-blessed (6, copied from
`tests/golden/smoke/2026-05-07_143246/withdft/`):

- `coulomb_efg_backbone.npy`
- `coulomb_scalars.npy`
- `mopac_coulomb_efg_backbone.npy`
- `mopac_coulomb_scalars.npy`
- `aimnet2_efg_backbone.npy`
- `mc_category_T2.npy`

All other 55 NPYs in `withdft/` were bit-identical with the prior
bless and were not touched.

### 2026-05-04 (earlier) — re-bless `nodft/` after AMBER charge slice

Reason: `data/ff14sb_params.dat` was regenerated by commit `6f66363`
(2026-05-01, the AMBER charge slice) via
`tools/amber/generate_ff14sb_pb_table.py`. The post-regen flat table
holds different per-atom partial charges from the pre-regen one. The
prior `nodft/` baseline was created 2026-04-24 against the pre-regen
table; running the smoke test against current code therefore showed
real drift across every charge-dependent array, while
charge-independent calculators (ring current, McConnell, ring chi,
etc.) stayed bit-identical.
