# Installability Plan

This is the producer install contract we want before building a Docker image.
Docker should consume this contract, not define a special path.

## Target Shape

The eventual supported flow should be:

```bash
make configure PREFIX=/opt/nmr-shielding PROFILE=producer-full
make build
make test-fast
make install
nmr-shielding-doctor
```

`producer-full` means the installed system can run the actual producer
surface, including AIMNet2, MOPAC, GROMACS trajectory support, AmberTools,
APBS, and tensorcs15-backed tripeptide lookup.

The eventual Docker target is a single-container producer-full appliance that
starts cleanly on a host with a documented minimum NVIDIA driver/CUDA
capability. This is an adviser requirement and is the release contract even
though it deliberately combines the producer process and PostgreSQL in one
container. The image should include the project install, MOPAC runtime,
PostgreSQL with tensorcs15 schema/data, AIMNet2/Torch user-space CUDA
libraries, and all non-driver runtime libraries needed by `nmr_extract`. The
host contract should be limited to Docker, NVIDIA container runtime support,
an adequate GPU/driver, and mounted input/output/data volumes.

## Runtime Closure

A full producer install must provide these runtime pieces from deliberate,
documented locations:

| Area | Required pieces |
| --- | --- |
| GROMACS | `libgromacs_mpi` or the chosen GROMACS library, matching MPI stack, and the internal headers currently needed at build time. |
| MOPAC | `libmopac`, the `mopac` executable, and matching Fortran/OpenMP runtime libraries. |
| AIMNet2/Torch | Torch C++ libraries, CUDA/cu13 user-space libraries, `libnvrtc-builtins.so.13.0`, a CUDA-capable runtime, and the `.jpt` AIMNet2 model. |
| PostgreSQL/tensorcs15 | `libpq`, a reachable tensorcs15 database containing the frozen tripeptide DFT fragment corpus, a restore procedure, expected row counts/checksums, and a DSN supplied without leaking secrets to logs. |
| AmberTools | `tleap` and `AMBERHOME` or an explicit configured `tleap` path. |
| APBS | APBS/MALOC/FETK libraries used by the bridge. |
| Chemistry/support libraries | OpenBabel, DSSP/cifpp, HDF5/curl/zlib/aec/sz, BLAS/LAPACK, OpenMPI, and their ABI-compatible transitives. |
| Installed data | `ff14sb_params.dat`, `calculator_params.toml`, optional Larsen grids, optional BMRB atom-name table, and configured locations for large model/data assets. |

## Container Shape

The primary deliverable is a single Docker image that can initialize/start a
local PostgreSQL cluster, verify tensorcs15, run `nmr-shielding-doctor`, then
run the requested `nmr_extract` job. That entrypoint needs real process
supervision and explicit shutdown handling so PostgreSQL is stopped cleanly
when the job finishes or the container receives SIGTERM.

Docker Compose can still be useful for development and CI validation because it
separates producer and database failure modes cleanly. It is not the release
contract unless the adviser requirement changes. Any Compose form should share
the same installed prefix, tensorcs15 schema/import scripts, assets, and doctor
checks as the single-container appliance.

## TensorCS15 Policy

tensorcs15 is a frozen production reference database of roughly 1.9 million
precomputed DFT tripeptide fragments. It is not regenerated by tests, Docker
builds, or install scripts. It is a runtime input to the live calculation:
protein runs query it to assemble shielding terms from matching tripeptide
fragments.

Installability therefore means the appliance can restore or mount a vetted
tensorcs15 snapshot, prove the expected schema/data identity, and fail loudly
if the database is absent, stale, incomplete, or incompatible with the query
code. Useful checks are row counts, dump/checksum identity, schema version,
and sentinel lookups that exercise the same query path used by the producer.

The tracked identity manifest is `config/tensorcs15.manifest.toml`. The
read-only checker is `scripts/tensorcs15-check.py`; installed builds expose it
as `nmr-tensorcs15-check`. The current manifest records 1,870,631
`raw_dft_calculations` rows, 20 tripeptides, 2 frame types, and the
`AAA`/`phi=-180`/`psi=-180` sentinel row used by the active perception tests.

## Known Blockers

1. CMake does not yet provide a complete install/export package. The first
   hook installs the producer executable, core data, and doctor script only.
2. `NMR_DATA_DIR` still defaults to the source tree for compatibility. A real
   install should configure with `-DNMR_USE_INSTALL_DATA_DIR=ON`.
3. The current build can capture machine paths in RUNPATH. CMake now has an
   opt-in `NMR_PROFILE=producer-full` / `NMR_REQUIRE_PORTABLE_DEPS=ON` gate
   that fails configure when core producer dependencies resolve through
   machine-local paths. The doctor reports
   these in default mode and `nmr-shielding-doctor --strict` fails on them.
   Treat strict mode as the release gate before calling an install portable.
   The 2026-05-28 configure also warns that micromamba library directories can
   hide system `libz`, `libpq`, and `libcurl`; producer-full must resolve that
   by using one deliberate dependency prefix/closure instead of mixed personal
   environments.
4. tensorcs15 now has a tracked identity manifest and read-only checker, but
   the actual snapshot location, restore mechanics, and dump provenance are not
   tracked yet. This is about faithfully serving the frozen DFT fragment
   corpus, not recomputing it.
5. Large model/grid assets are not copied by default. Copying or vendoring
   them should be an explicit producer-full decision because they affect disk
   use and image size.
6. A root `make configure` / `make install` wrapper is still future work. The
   repo currently ignores root `Makefile` to avoid accidental in-source CMake
   output, so adding that entry point requires an explicit tracked exception.
7. The CUDA host contract is not yet explicit. We need a documented minimum
   NVIDIA driver/GPU capability and a doctor check that reports CUDA visibility
   without launching expensive workloads by default.
8. The single-container appliance entrypoint is not designed yet. It needs
   Postgres init/restore idempotency, database readiness checks, clean signal
   handling, log routing, and a way to fail loudly when tensorcs15 is absent or
   stale.
9. Compose service boundaries may still be useful for development/CI, but they
   are secondary to the adviser-required appliance image.

## Current Gate Status

As of 2026-05-28, the normal local configure succeeds with:

```bash
cmake -S . -B build \
  -DNMR_PROFILE=local \
  -DNMR_REQUIRE_PORTABLE_DEPS=OFF \
  -DNMR_USE_INSTALL_DATA_DIR=OFF \
  -DNMR_ENABLE_NATIVE_ARCH=ON
```

The release/container configure is intentionally not green yet:

```bash
cmake -S . -B build \
  -DNMR_PROFILE=producer-full
```

It currently fails the new CMake portability gate because GROMACS, reduce,
MOPAC, Torch/cu13, and CUDA resolve through local paths. This is the expected
state until those dependencies are supplied from a deliberate producer prefix.
After the failure check, the build cache was restored to the local profile.

## Doctor Contract

`nmr-shielding-doctor` starts as a non-destructive preflight. It should remain
safe to run on a dirty working tree or installed prefix. The default mode:

- verifies the producer binary exists;
- checks dynamic linker output for missing libraries;
- reports suspicious local RUNPATH or library resolutions;
- checks configured paths for MOPAC, `tleap`, ff14SB params, AIMNet2 model,
  CUDA/cu13 runtime, a writable or runtime-creatable temp directory, and
  optional Larsen/BMRB paths;
- checks that a tensorcs15 DSN is present without printing the DSN value.

Run `nmr-tensorcs15-check` for the read-only tensorcs15 restore/integrity
check. It connects to PostgreSQL, compares the live database against the
tracked manifest, and does not print the DSN.

For release/install checks, run `nmr-shielding-doctor --strict`. Strict mode
promotes machine-local `ldd`/RUNPATH resolutions to failures, including
`/home`, `/shared`, `/mnt`, `/opt/orca`, and `/usr/local/cuda` paths. CMake now
prefers an installed `$ORIGIN/../lib` RUNPATH and disables automatic installed
link-path harvesting by default; dependency libraries still need to be provided
from a deliberate producer prefix before strict mode can pass.

`--deep` currently includes the tensorcs15 manifest check. Future deep modes
can add actual AIMNet model loading, MOPAC smoke runs, and `tleap` smoke runs.
Those should remain opt-in because they can consume GPU time, CPU time, or
database credentials.

## Disk Policy

Do not copy dependency trees, model assets, fixtures, or generated outputs as
part of this cleanup without explicit approval. Install rules may describe the
future target layout, but actual install staging and image construction should
be deliberate disk-using steps.
